# CLAUDE.md

## Rules

- Never add "Co-Authored-By", "Generated with Claude Code" or any Claude/Anthropic attribution to commits, PR titles, PR bodies or code comments. Do not commit unless I ask.
- The LLM never decides a price. Prices come only from the negotiation engine's deterministic code.
- All frontend work follows docs/DESIGN.md, including its banned list.
- Secrets live in git-ignored .env files; keep .env.example files up to date.
- Work in small tested increments; run the tests before saying a task is done.
- Never kill or restart processes you didn't start. Use the PID of your own run; never pkill by pattern.

## Layout

- `backend/`: Spring Boot 3.5, Java 21, Gradle (Kotlin DSL), base package `com.latestay`. DTOs are Java records. Migrations in `src/main/resources/db/migration`. Tests: `./gradlew test` (Testcontainers, needs Docker); live LLM tests are tagged `llm` and run only via `./gradlew llmTest`.
  - `com.latestay.negotiation` is pure Java (ArchUnit-enforced): no Spring, DB or LLM.
  - Persistence wraps the engine: `com.latestay.session` stores `SessionSnapshot`s and rebuilds sessions with `NegotiationEngine.restore`. SQL is plain `JdbcClient` (no JPA entities); `com.latestay.hotel`, `com.latestay.stay` (search, `StayWindow`, night_of), `com.latestay.admin` (HTTP basic). Local seed data: `seed/local-hotels.json`, loaded by `LocalSeedData` locally and on staging only (`latestay.seed.enabled`; production refuses it).
  - Integration tests share one PostGIS container: each test class creates its own hotels in its own map area and never assumes empty tables.
  - `com.latestay.hold`: room holds. Rooms available = SQL function `rooms_available` (latest report − active holds − live bookings since the report); never read `nightly_availability.rooms_free` directly for selling. Agreeing takes a hold through `RoomGuard` inside the agreeing transaction. `com.latestay.phone`: WhatsApp OTP before booking (hashes only, signed device cookie). Booking states and rules: docs/ARCHITECTURE.md#booking-states; /refund-policy states them for travellers, so change both together.
  - `com.latestay.booking`: bookings from AGREED sessions. Status changes only through `BookingService.move`, guarded by `BookingTransitions` (the state table); timeouts in `BookingJobs` (injected `Clock`; `latestay.jobs.enabled=false` in tests, which call the jobs directly). Money comes from the session's agreed price, never the client. `com.latestay.payment`: Razorpay gateway (REST, no SDK), signatures; `FakeRazorpayGateway` only when `latestay.razorpay.allow-fake` (local profile, tests). Every webhook handler must stay idempotent.
  - `com.latestay.whatsapp`: the owner channel (Cloud API). Inbound is stored first by `wa_message_id` (idempotent), then parsed by `OwnerReplyParser` (regex only); outbound is queued in `whatsapp_message` and sent by `WhatsAppSender`. Business-initiated messages must be one of the approved templates in docs/whatsapp-templates.md; keep that file and `WhatsAppMessages` in sync. Booking notifications listen for `BookingStatusChanged`.
  - `com.latestay.ledger`: what LateStay owes hotels, append-only `ledger_entry` in paise (new money columns are paise; old rupee ones stay). Entries are written only from `BookingService.move` / refunds, at most once per booking and type; weekly `Settlements` (Monday 10:00 IST). `com.latestay.owner`: the owner page, signed in by a WhatsApp "hisaab" link; every `/api/owner/**` endpoint takes an `OwnerHotel` from the cookie and never a hotel id. `com.latestay.photo`: uploads go to the imaging service and then S3-compatible storage (`FakePhotos` in tests).
  - Every `@Scheduled` job needs a `@SchedulerLock` (ShedLock, `com.latestay.jobs.SchedulerLockConfig` names) and a `JobRuns.ran(...)`; `TwoInstancesIT` enforces both. `APP_ENV` (local / staging / production) gates seed data (`latestay.seed.enabled`) and live keys.
  - `com.latestay.review`: reviews and the Bayesian `Rating` (no seeded ratings); `com.latestay.reliability`: 30-day hotel reliability, search ranking and pausing; `com.latestay.pricing`: the engine's `PricingContext` inputs (rooms free / total rooms, weekend, `season_period`); never pass a floor or a price through these. Groups: a negotiation and booking can cover two rooms (`negotiation_room`, `booking_room`, `booking.rooms`); holds are all or nothing. `com.latestay.share`: "Share with family" links (never a code, phone number, name or price). `com.latestay.town`: town page data. Integration tests run with `latestay.pricing.version=1` (the old rules) unless they extend `OccupancyPricingSupport`; new test hotels go on their own longitude, away from `TestBookings`' spots.
  - `com.latestay.analytics`: funnel events. Only whitelisted properties per event (`AnalyticsEventName`), cleaned by `AnalyticsSanitizer`; never put a name, phone number or code in an event. `com.latestay.promo`: promo codes (paise, whole rupees; `PROMO_SUBSIDY` keeps the hotel's payout whole). `com.latestay.digest`: `/admin/today`, the 09:00 `morning_digest` and `/admin/funnel`. Tests that need exact totals or several app instances use `FreshDatabase` (its own migrated database in the shared container).
  - `com.latestay.web`: rate limits (Bucket4j, in memory, so one instance), `Pii.mask` / `Pii.scrub` (never log a full phone number; production JSON logs scrub every field too), Sentry scrubbing and the `prod` startup checks. New env vars also go in the tables in docs/DEPLOY.md.
  - `com.latestay.conversation` wraps it with the LLM. Every reply must pass `ReplyValidator` (only the engine's amount) or fall back to `ReplyTemplates`.
- `web/`: Next.js 16 App Router, TypeScript, Tailwind v4 (theme in `src/app/globals.css`). No `cacheComponents`: each page is an async server component that fetches its first data (`lib/server-fetch.ts`) and passes it to its client screen as TanStack `initialData`, so the LCP photo is in the first HTML; keep LCP content out of Suspense boundaries. Service worker: Serwist (`src/app/sw.ts`, built by `src/app/serwist/[path]/route.ts`); never cache admin, owner, dev or webhook traffic. Sentry is errors-only and scrubs phones (`lib/sentry-scrub.ts`). Checks: `npm run lint && npm run build`. Town pages (`/towns/[town]`) are static and rebuilt hourly; `NEXT_PUBLIC_APP_ENV=production` is the only indexable environment (robots.txt, sitemap.xml). Read `web/AGENTS.md` and the bundled Next docs before using unfamiliar Next APIs.
- `mobile/`: Capacitor 8 iOS/Android apps that load the web app (docs/MOBILE.md, docs/ARCHITECTURE.md#mobile-apps). The version lives only in `mobile/package.json`; `node scripts/configure.mjs` applies it and the app ID (`APP_ID`, `APP_ENV`, `SERVER_URL`) before `npx cap sync`. Firebase config files and signing keys never go in git. Checks: `npm test` in `mobile/`; builds run in `.github/workflows/mobile.yml`. In `web/`, app-only code stays in `src/lib/native` and `src/components/native`, gated by `isNativePlatform()`, with plugins imported lazily and CSS under the `native:` variant: the website must stay pixel-identical (`npx playwright test -c playwright.unchanged.config.ts` against baselines taken before a change). `e2e/app-sim.ts` simulates the app's WebView for `e2e/app-shell.spec.ts`. `com.latestay.push`: device tokens and app notifications (never a code, phone number or name in a payload).
- `imaging/`: photo processor, Node 22 + sharp (JPEG/PNG in, EXIF-free WebP at 400/800/1600 px out, no storage). Checks: `npm test`. Local: `docker compose up imaging photos` (photos = S3Mock standing in for R2).
- `sim/`: negotiation simulator, Python 3.12 + uv, package `latestay_sim`. Talks to the backend only over HTTP. Checks: `make sim-test`; end-to-end: `make sim-offline` against a local-profile backend; `make sim-compare` writes `sim/reports/pricing-compare.md` (kept in git).
- `docs/`: DESIGN.md, ARCHITECTURE.md, DEPLOY.md (staging and production, every env var), RUNBOOK.md (restore, roll back, rotate secrets). `scripts/`: `backup.sh` and `restore-drill.sh` (run by `.github/workflows/backup.yml`).

## Tailwind tokens (from docs/DESIGN.md)

- Colours: `canvas`, `soft`, `ink`, `ink-secondary`, `hairline`, `ember`, `ember-button`, `ember-button-hover`, `pine`, `error`. The default palette is removed on purpose. Primary buttons use `ember-button` (white on `#D9572B` fails AA); only `Button variant="primary"` and the search pill's round button use it.
- Web components live in `web/src/components/` (Tailwind only). `/admin` (in `src/app/admin/`) uses the same tokens with denser controls and no ember; its API types are hand-written in `src/lib/admin-api.ts` because the admin API is kept out of the public OpenAPI spec (so is the owner page's: `src/lib/owner-api.ts`). API types come from `web/openapi.json` (written by the backend's `OpenApiSpecIT`) via `npm run gen:api`. Checks: `npm test`, `npm run lint`, `npm run build`; `npm run screenshots` (Playwright, needs the local backend) writes `web/screenshots/`.
- Sizes `text-32` … `text-12` (plus `text-code`, 56 px, for the booking pass's desk code only); weights `font-normal` / `font-medium` / `font-semibold`.
- Radii `rounded-card` (12px), `rounded-control` (8px), `rounded-full` (pill). Only shadow: `shadow-float`.
- Prices: `tabular-nums` + `Intl.NumberFormat('en-IN')`.
